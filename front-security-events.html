Making Front visible to enterprise security teams

A settings page that streams sign-in, MFA and session events into a customer's own security tools.

TL;DR. When a security incident happens, enterprise security teams investigate in their SIEM (Splunk, Microsoft Sentinel, Panther), and Front sent them nothing: no sign-ins, no MFA, no sessions. Security reviews ended in standing exceptions, and some deals stalled. I designed how a company admin connects Front to their SIEM: presets for each tool, a test event before anything goes live, and a status page built to be trusted, not used. Launched with 6 enterprise accounts, with custom connections for teams that use their own collector.

Context

What a SIEM is, and why it matters

A SIEM (Security Information and Event Management) is where a company's security team collects logs from every critical tool, so they can follow an incident across systems on a single timeline. Enterprise buyers expect each vendor to send its events there. Front recorded sign-ins, failed logins, MFA and sessions, but kept that data inside Front.

The problem

Front was a black box in every security review

After an incident, a customer couldn't tell from their own security tool who got into Front or from where. One large enterprise customer depended on a security exception that had to be renewed every year; others raised it at renewal; prospects in regulated industries listed native SIEM logging as a deciding criterion.

Key decisions

01

A page built to be trusted, not used

Starting point
most settings pages are places admins come back to. This one isn't. Nobody reads these events in Front; they read them in their SIEM.
What we learned
the page only needs to do three jobs: point the stream somewhere, prove it's working, and recover it when it breaks.
What shipped
no in-app event viewer and no filters. Every connection receives every event, and the page focuses on status and recovery.
02

Name things the way security teams do

What we tried
we compared the words other products use. Developer platforms say destination, identity tools say stream, and products that receive data say source.
What we learned
there's no shared convention, and the word admins already have in mind comes from their SIEM tool.
What shipped
copy that names the tools (Splunk, Sentinel, Panther) and plain labels like "Connect your SIEM".
03

A preset for each SIEM

Each SIEM connects differently: a token for Splunk, a shared secret for Panther, custom fields for Google SecOps or a company's own collector. Instead of one long generic form, the admin picks their tool and sees only the fields it needs. Credentials are masked and never shown again after saving; rotating means pasting a new one.

Custom connections. Some security teams don't send logs straight to a SIEM; they route them through their own collector first. For them, a custom connection lets the admin set the endpoint, the authentication method and their own headers, with the same test and status as the presets.

Why: presets make the common case fast, and the custom option means no enterprise team is left out because of how their stack is built.

04

No stream goes live untested, and every failure says what to fix

Connecting sends one sample event, and the stream only turns on if it arrives. When something fails, the admin sees the specific reason (invalid credentials, unsafe URL, missing permissions, rate limit) and a reconnect flow, instead of a generic error.

Scope calls

Streaming is all or nothing; customers filter in their SIEM. Events aren't stored in Front in the first release, which got the core value out sooner. On SSO accounts, some fields stay explicitly "unknown" because the identity provider owns them, and the data says so instead of guessing.

Impact

Launched with 6 enterprise accounts streaming sign-in, MFA and session events into their SIEM, removing a recurring exception from their security reviews. Custom connections extended it to teams that route logs through their own collector. [Customer quote or number of security reviews unblocked]

Looking back

The best version of this page is the one admins forget about. Designing for trust meant cutting features, not adding them.
